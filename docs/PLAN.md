# Rex — build plan

Rex is a local-first macOS desktop app for personal bots. Each bot has its own
instructions, model, tools, workspace folder and memory. It is built on the
existing Go `agent-runtime` and starts from the working code in
`~/git/personal-agent` (rebased onto the current runtime), not from Helpin's
support-desktop shell.

## Architecture

```
Tauri 2 + React (webview)
   │  HTTP + SSE on 127.0.0.1:<port>, bearer token handed over by a Tauri command
   ▼
rex-host (Go sidecar, supervised by Tauri via stdin pipe)
   │  owns: bots, conversations, routines, settings, secrets (macOS Keychain),
   │        memory (agent-runtime/memory SQLite library), workspace provider,
   │        run-scoped MCP server (memory tools), scheduler, idle consolidation
   ▼
agent-runtime (Go sidecar, supervised by rex-host)
   store=sqlite, runtime_kind=native_sdk, events persisted + SSE
   providers: anthropic / openai / openrouter (env keys) and
              openai_compatible (LM Studio / Ollama) via approved model_endpoints
              + per-run model credentials
```

Data directory: `~/Library/Application Support/ai.rex.desktop/`
(`rex.db`, `runtime.db`, `memory.db`, `rex.log`). Bot workspaces default to
`~/Rex/<bot-slug>/`. Skills live in `~/Rex/skills/*.md`.

### Key decisions

| Decision | Choice | Why |
|---|---|---|
| Starting point | Copy personal-agent source into `rex/`, rename | It already has the sidecar chain, conversations, approvals, provider settings |
| Execution backend | `native_sdk` only | Runtime rejects `codex`/`opencode` (`execution_policy.go:54`) |
| Local models | `openai_compatible` + `model_endpoints` in generated app config | Runtime's supported path for LM Studio/Ollama Chat Completions |
| Bot state | Host DB is the source of truth; synced to runtime agents with `PUT /v1/agents/{id}` | Keep product state out of the execution engine |
| File workspace | `execution_config.workspace.mode = host_prepared` + app `workspace_provider` (HTTP) served by the host, returning the bot's folder | Uses runtime's existing lease contract; per-bot folder scoping |
| Memory | Host imports `github.com/helpin-ai/agent-runtime/memory` (SQLite backend) directly, one bank per bot (or an explicit shared bank) | Retain/Recall/Forget with source documents already exists |
| Memory tools for bots | Run-scoped MCP server on the host, URL carries a per-run token that maps to the bot's bank | Bank chosen by host, never the model |
| Secrets | macOS Keychain (`go-keyring`), never in SQLite, never sent to the webview | Plan requirement |
| Local API auth | Random bearer token generated by Tauri, passed to host via env and to the webview via a Tauri command; CORS locked to the app origin | Other local processes can't drive the bots |
| Shell tool | Off by default, always approval-gated when on | No OS sandbox on macOS |

## Milestones and verification gates

Each milestone ends with an explicit check. Work does not move on until the
check passes or the gap is written down.

### M0 — Bootstrap
- `git init`, copy personal-agent sources (no binaries / node_modules / target).
- Rename everything to Rex (`rex-host`, `ai.rex.desktop`, module `github.com/helpin-ai/rex`).
- `go.mod` uses `replace github.com/helpin-ai/agent-runtime => ../agent-runtime`.
- **Gate:** `go build ./...`, `go test ./...`, `pnpm build`, `pnpm test` pass.

### M1 — Desktop connection on the current runtime
- Default bot → `native_sdk`; remove Codex auth/device-code paths.
- Provider settings: Anthropic / OpenAI / OpenRouter keys, plus "Local model server" (base URL + optional key). Generated `AGENT_RUNTIME_APP_CONFIG` includes `model_endpoints`; runs carry `model` + `model_credential`.
- Secrets move to Keychain (with one-time migration from the old encrypted settings table is unnecessary — fresh app).
- Local API bearer token + CORS lockdown; Tauri command `host_connection()`.
- Connection test endpoint: lists models and performs one tool-call round trip.
- **Gate (scripted against LM Studio):** start host → create conversation → send message → stream SSE → cancel a second run → restart host → conversation and transcript still load.

### M2 — Core bot experience
- Bot profiles (host table): name, avatar emoji/color, instructions, provider, model, capabilities (files read / files write / shell / web / browser / memory), approval mode, workspace folder, memory scope (private | shared).
- Capability → runtime `allowed_tools` mapping; sync to runtime on save.
- Workspace provider endpoint on the host (`/runtime/workspaces/prepare|finalize|cleanup`).
- Conversations per bot; attachments (copied into the bot workspace `inbox/` and referenced in the message).
- Tool activity, approval cards, artifacts (files written in workspace listed per run).
- UI: sidebar of bots like contacts → conversations → chat pane with streaming transcript; bot editor; settings.
- **Gate:** two bots (A: read-only files, B: read/write files with approval) each complete a file task in their own folder; B asks for approval before writing; A cannot write; conversations stay separate.

### M3 — Memory
- Memory service in host: open `memory.db` with the provider configured from settings (extraction model + embedding model; defaults to the local server, e.g. `nomic-embed`).
- After each settled turn, asynchronously retain that turn as a source document (`conv/<id>/run/<run>/turn/<n>`), bank = bot's bank. Conservative: skip turns with no user content; never retain tool outputs; redact obvious secrets.
- Retrieval: the runtime's target-context endpoint recalls with the latest user message and injects top facts as reference data.
- Bot tools via run-scoped MCP: `memory_recall`, `memory_remember` (explicit), `memory_forget_source`.
- Idle consolidation scheduler (no active runs for N minutes).
- Memory view: per bot list of sources and facts, forget source, add/correct a preference (correction = new user-authored source; old source can be forgotten).
- **Gate:** tell bot a preference → restart → bot uses it; correct it → bot uses the correction; forget the source → bot no longer recalls it.

### M4 — Browser + MCP
- Enable runtime browser tools (agent-browser CLI) with a persistent per-bot profile directory; "Take over" opens the bot's browser headed; while the user holds control, the host rejects browser tool calls (approval gate) and the bot is told to wait.
- MCP connections settings: URL + optional bearer token (Keychain), discover tools, mark read/write, attach to selected bots as run-scoped MCP servers.
- **Gate:** bot researches a site and saves a report artifact; one MCP server used end to end.

### M5 — Skills + routines
- Skills: editable markdown files in `~/Rex/skills`; enable per bot; compiled into the bot's system prompt.
- Routines: interval / daily-at-time schedules persisted in SQLite; claim-before-start with `host_run_id` idempotency; bounded retries (max 2); consecutive-failure auto-pause; minimum interval 15 min; missed-run policy = run once if missed by < 1 h, otherwise record `missed`; run history UI; banner that routines need the Mac awake and Rex running (tray keeps it resident).
- **Gate:** routine runs once; a failing routine shows the failure; restart during a routine does not duplicate it.

### M6 — Package + harden
- Interrupted-run recovery on host start (mark/resume, never re-execute side effects).
- Schema migrations table, structured logs + "Open logs" menu item, sidecar exit verification.
- `pnpm tauri build` produces `Rex.app` / `.dmg` (unsigned locally; signing and updater documented, need Apple Developer ID).
- **Gate:** built `.app` launches, completes the M1–M3 gate flows, quitting leaves no `rex-host` / `agent-runtime` processes.

## Testing approach

- Go unit tests for host packages (store, bots, memory service, scheduler, workspace provider).
- `scripts/e2e.sh`: boots the host against LM Studio (`qwen/qwen3.6-35b-a3b`, `text-embedding-nomic-embed-text-v1.5`) in a temp data dir and runs the gate scenarios through the HTTP API.
- UI checked by running the real Tauri app and through the Vite dev page.

## Out of scope for this release

Mobile, team sharing, marketplace, cloud execution, bundled inference,
arbitrary desktop control, Windows/Linux, auto-update server.

### Decisions made while building

- **Memory extraction** uses Rex's own small-schema extractor (`internal/rex/extractor.go`) on top of the `agent-runtime/memory` storage, embedding and recall. The upstream strict schema made local models (gpt-oss in LM Studio) generate garbage or never stop.
- **Only the user's words are retained.** Retaining the bot's reply let forgotten facts return through answers that repeated recalled memory.
- **Browser profiles** are per bot. Rex pre-launches the runtime's per-run agent-browser session with the bot's profile, so agent-runtime is unchanged. Takeover is allowed only while the run is paused.

### Resolved: file writing and shell (Seatbelt)

Implemented in agent-runtime as the opt-in `seatbelt` isolation mode (`docs/plans/2026-10-05-macos-seatbelt-command-sandbox.md` there). Rex starts the runtime with it and turns on writing and shell only when `/v1/capabilities` reports `execution_isolation: seatbelt`.

### Background

agent-runtime admits `write_file`, `edit_file`, `apply_patch` and `run_command` only when the engine is an isolated coding worker (`CodingWorker`). The API server never sets this in lightweight mode, while the local CLI does for trusted local use. Rex keeps these capabilities off and explains why in the UI. To turn them on, choose one of:

1. Add an explicit opt-in to agent-runtime for trusted single-user local hosts (as the CLI does), or
2. Run a separate isolated execution worker for desktop bots.

Either one is a security decision for the runtime owner.
